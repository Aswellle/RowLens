# RowLens 竞品与差异化策略

## 结论

本地数据预览已经是一个成熟的小赛道。RowLens 不应以“支持 CSV/TSV、能搜索、完全本地”作为主要差异点；这些能力已被多个产品覆盖。当前目标是提供一个 **数据清洗可预览、步骤可组合、导出语义清楚** 的轻量工具。

## 竞品快照（需在发布前复核）

| 项目 | 已知定位 | 对 RowLens 的启示 |
|---|---|---|
| [CSV_Viewer](https://github.com/mynl/CSV_Viewer) | 浏览器内 CSV/TSV 查看、排序、过滤，也关注大文件 | 常见查看功能不是差异化；RowLens 要在清洗步骤与导出预览上做强 |
| [dataloupe](https://github.com/aurelio-nakamura/dataloupe) | 离线数据探索，能生成独立 HTML 并提供 SQL 查询 | 不要竞赛“所有格式、所有分析能力”；聚焦一次性数据清洗工作流 |
| [LeanRows](https://github.com/abooodbah/leanrows) | Windows 原生只读的大文件浏览器，涵盖 CSV/TSV/JSONL/NDJSON/日志 | RowLens 不应声称自己是最高性能的大文件读取器；它是浏览器内处理与导出工具 |
| [CEESVEE](https://github.com/soldforaloss/ceesvee) | Tauri/Rust/React CSV 查看编辑器，强调大型文件与数据往返保真 | 避免承诺与成熟原生编辑器相同的无损编辑能力；源文件只读是首版安全边界 |
| [OpenRefine](https://openrefine.org/) | 成熟的数据清理与转换工具 | RowLens 以更低的开始成本和轻量本地 Web 体验作为差异，而不是功能广度 |

## 目标差异化

### 一次清洗，不是一整套数据平台

- 不要求用户创建项目、配置数据库或写 SQL。
- 每个清洗步骤以“规则 + 影响统计 + 预览”呈现。
- 清洗流程能逐步启停与重置。
- 导出前看到行数、列数和可能被安全转义的值。
- 用户知道自己导出的是完整数据还是过滤结果。

### 信任是体验的一部分

- 文件内容留在浏览器本地，静态站点无文件上传接口。
- 安全导出不悄悄篡改原始源文件。
- 不支持的格式直接说明；异常行数量可见。
- 真实基准和已知限制公开展示。

## 应避免的方向

- 不要在首版同时添加 SQL、图表、AI 建议、Excel 支持、数据库连接和用户账户。
- 不要把清洗规则自动应用到源文件。
- 不要用“100% 安全、无限大、比所有工具快”做营销承诺。
- 不要为了 Stars 复制竞品 README、视觉设计或专属功能；竞品研究只用于理解用户任务和市场缺口。

## 发布验证假设

首版发布后观察：

- 用户是否完成导入、清洗、导出完整路径；
- 用户最需要的清洗动作是什么；
- 哪些文件格式/大小是实际需求；
- 首次体验中在哪里取消或失败。

如果用户主要把 RowLens 当作只读查看器，重新评估其差异化是否成立，再决定是否继续扩张。
