# RowLens 数据处理契约与算法规则

这是测试与实现共同遵守的规范。遇到歧义，先更新此文档和测试，再改代码。

## 1. 术语

- **物理行**：文本文件中的换行位置；CSV 引用字段可包含换行，因此物理行不等于记录序号。
- **记录/数据行**：解析器识别出的 CSV 记录或 JSONL 记录。
- **rowIndex**：成功导入的逻辑数据记录，从 0 开始。必须与物理行号分开。
- **缺失值**：没有该字段；CSV 空单元格为 `""`，JSON `null` 用显示字符串 `null` 或空值策略明确表示，禁止混淆。
- **原始值**：解析器读出的字段字符串，不含额外 trim / 类型推断。

## 2. CSV/TSV 解析契约

- 不使用简单字符串 split。
- 默认 UTF-8；若出现替换字符或 BOM，应在摘要里提示可能存在编码问题。首版不实现任意编码自动侦测；允许后续扩展编码选择。
- 去除 UTF-8 BOM 只应影响文件开头的标记，不得删除用户字段中的类似字符。
- 支持逗号/制表符、双引号包裹、双双引号转义和引号字段跨行。
- 行尾支持 LF 与 CRLF。空文件、只有表头文件、最后一个字段无换行均应有确定结果。
- 空行策略必须显式配置，不能让解析库默认值隐式决定数据丢失。默认保留可解析的空记录，交给清洗动作决定是否删除；若解析库无法区分，应在文档中说明具体行为并写测试。
- 重复 header 通过源位置生成 `c0/c1/...` 等稳定 ColumnId，显示名重复也不覆盖值。
- parse warnings 有上限，例如 UI 只展示前 20 条示例，其余显示累计数量；原始内容不写 console。

## 3. JSONL / NDJSON 解析契约

- 使用 `File.stream()` 或 `Blob.slice()` 分块读取；`TextDecoder.decode(chunk, { stream: true })` 保留跨 chunk UTF-8 字符完整性。
- 缓冲区只保留当前未完成的一行，必须有配置的最大行长度保护（初始建议 5 MiB，实测后调整）；超限行作为错误记录处理，不让单行占满内存。
- `\n` 和 `\r\n` 都支持；文件结尾最后一条记录可以无换行。
- 忽略纯空白行应是明确选项/默认契约；推荐默认跳过纯空白行并计入 warning，而不计为数据行。
- 每条有效记录必须是非 null 的 JSON object。数组、字符串、数字、布尔、null 记录计为格式错误，并能继续处理后续行。
- schema 按第一次见到的 key 顺序累积；后续新 key 会 append 新列。列 ID 使用内部序号，绝不把任意输入 key 当作对象原型/DOM 属性。
- 嵌套值通过 `JSON.stringify` 稳定显示；循环结构不可能来自 JSON 原文，但 stringify 失败仍需 catch。
- JSON 重复键以标准解析器最终值为准，但文档明确此限制；不得声称保留重复 JSON key 的全部值。

## 4. 字符串与比较

- 默认保留空格、大小写、前导零和日期格式。
- 默认搜索：`toLocaleLowerCase` 或指定稳定 locale 的大小写不敏感 literal substring；不得解析输入正则/表达式。
- 搜索框语法（ADR-034）：空白分隔的 term 之间是 AND；`列名:文本`（表头精确匹配、大小写不敏感）把该 term 限定到那一列；含空格的表头用双引号（`"First response (h)":14`），引号只在这个位置有意义，其余位置按字面搜索。前缀不是任何表头时整个 term 仍是普通子串（URL、时间戳不受影响）。重复表头搜索**所有**同名列，绝不静默挑一个。`列名:`（空值）等价"不过滤"，不触发扫描。语法层永远不引入正则/通配符。
- 空筛选值视为“该列不过滤”。
- 排序默认为 UTF-16 字符串排序并稳定；用户可通过显式类型选择进行数值排序（ADR-035，列头"Treat as numbers"开关，绝不自动推断）。数值解析规则固定为：去首尾空白后，十进制（可选符号/指数）或严格 en-US 千位分组（`1,050`，组必须恰为三位）；十六进制/Infinity/NaN/币种符号一律不算数。混合列分区排序：数字区（数值比较）→ 非数字文本区（字符串比较）→ 空单元格，分区顺序在升降两个方向都保持不变，仅分区内比较随方向反转；同值保持原始顺序（稳定）。日期不解析——ISO-8601 文本在字符串序下本来就正确。
- null/missing/empty 的顺序规则需在实现和测试中固定；建议：缺失值最后，其他值按字符串排序；升序/降序都不得改变相同值原始顺序。

## 5. Trim whitespace

- 默认只修剪 ASCII/Unicode 字符串两端的空白，不修改内部空格。
- 作用范围可以是所有列或选定列。
- 应报告“有变化的单元格数”，而不只是行数。
- 不自动 trim 表头，除非用户明确请求；显示 label 与原始 key 的处理要分开。

## 6. Remove empty rows

默认定义：选定列中的值全部为空或 trim 后为空，即符合删除条件。用户可以将范围设为全部列或特定列。若只检查部分列，提示该操作意味着“这些列为空就删除”，即使其他列有值。

## 7. Remove duplicates

- 全行模式：比较所有导出字段（按当前列顺序）；指定键列模式：只比较选择的键列。
- 默认严格比较，不隐式 trim、不改变大小写、不转数字。
- 按输入顺序保留第一次出现的记录；结果顺序稳定。
- 对复杂值使用规范化的列值串来比较；若只用哈希，发生 hash collision 后必须再次逐值比较。
- 重复计数以被删除的行数计；不将源数据真的删除。

## 8. 清洗步骤组合

- 顺序执行，后续步骤读取此前步骤的逻辑输出。
- 停用步骤相当于忽略，不删除步骤配置。
- 任一步骤参数变化后产生新的 pipeline revision；旧任务结果不能覆盖新 revision。
- 无论在 UI 里怎样隐藏列，都不得改变源数据；隐藏与 Select columns 是不同概念。
- 所有步骤应可通过 JSON 序列化、反序列化并复现相同结果。

## 9. CSV 导出契约

- UTF-8，CRLF 行尾，双引号包裹只在必要时使用，字段内双引号重复转义；逗号、换行和双引号必须正确处理。
- 导出顺序确定：所选列顺序 + 当前记录原始相对顺序（除非用户主动排序并选择按视图顺序导出；MVP 推荐默认按当前可见结果顺序并在 UI 明确说明）。
- `Spreadsheet-safe` 模式应只改变有公式注入风险的字段；报告影响单元格数量。防护实现必须记录策略并有专门测试。
- `Raw` 模式保留字段字符串，但 UI 对电子表格公式注入风险提供非阻断警示。
- 为避免把 CRLF、tab、leading whitespace 等风险遗漏，按 OWASP 最新指南复核危险前缀检测；不要只检测第一个字符 `=`。
- 导出到浏览器下载必须 revoke Object URL；不能过早 revoke 造成下载失败，也不能永久保留 URL。

## 10. 数据集生命周期

- `importing` → `ready` 只能在所有批次成功持久化和元信息 finalize 后转移。
- 取消/错误时不得暴露部分记录为完整数据集。清理失败要留待启动时重试。
- 每次重载应用后先清理过期中断数据集，再展示数据集列表（MVP 可只显示当前 dataset）。
- 用户点击“移除文件”时确认清除本应用内暂存数据，不影响源文件。
