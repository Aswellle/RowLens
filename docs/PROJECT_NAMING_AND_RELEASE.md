# 名称、许可证与开源发布策略

## 1. 名称状态

| 工作名 | 状态 | 发布前必须做的检查 |
|---|---|---|
| RowLens | 暂定 | GitHub 仓库名、NPM 包、域名、搜索可发现性和商标冲突 |
| RepoRead | 暂定 | 近名 `RepoReady` 已有多个项目；必须检查是否造成混淆，不得默认能注册同名 |
| CleanSlate | 暂定 | 名称通用且容易重名；检查 GitHub、NPM、域名及商标 |

不因为名称可用就自动把项目发布到用户账户；发布、创建远程仓库、推送 release 等外部动作须由用户明确授权。

## 2. 许可证建议

- RowLens：MIT，适合轻量开发者工具；若选 MIT，添加完整 LICENSE 文件并在 README 标明。
- RepoRead：MIT，同样适用于零依赖 CLI；需确保规则或模板没有复制不兼容许可证内容。
- CleanSlate：MIT 可行，但二进制格式处理器、元数据解析依赖及测试样本必须各自核验许可证和来源。

以上是建议，不是法律意见。正式发布前由项目维护者确认许可证选择。

## 3. 每个仓库的最小发布资产

- `README.md`：一句话定位、动图/截图、功能和非目标、安装/运行、数据隐私、兼容性、路线图、贡献指南。
- `LICENSE`、`CONTRIBUTING.md`、`CODE_OF_CONDUCT.md`、`SECURITY.md`。
- `CHANGELOG.md` 或 GitHub Releases 约定；版本号与行为变化可追踪。
- GitHub Issue 模板、PR 模板、CI 工作流、依赖更新策略。
- 示例数据必须是合成数据，不要提交个人真实数据或带有真实 GPS/个人信息的图片。
- 安全报告不得要求用户公开提交敏感原始文件。

## 4. 社区传播

- 使用真实 UI 截图或 15–30 秒的无声 GIF 展示一个问题如何被解决。
- README 首屏只保留项目名、单句定位、演示图、安装和核心承诺。
- 写清楚“适合谁”和“不适合谁”，避免功能堆砌。
- 用可复现基准说明性能，而非写“最快”“无限大”“绝对安全”。
- 发布后优先响应复现清楚的 bug 和高价值贡献，不用虚假 Stars、刷量或误导性宣传。
